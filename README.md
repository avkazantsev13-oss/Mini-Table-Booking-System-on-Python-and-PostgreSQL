# Мини-система бронирования столов

Моделируется небольшое заведение: учёт гостей и столов, брони на интервалы времени, проверка свободен ли стол в выбранном слоте, запрет пересечений броней по одному столу.

## Технологии

| Компонент | Роль |
|-----------|------|
| **PostgreSQL** | Хранение данных |
| **psycopg2** | Драйвер Python ↔ PostgreSQL |
| **python-dotenv** | Параметры подключения из `.env` |
| **tkinter (ttk)** | Графический интерфейс (стандартная библиотека Python) |

Зависимости: `requirements.txt` (`psycopg2-binary`, `python-dotenv`).

## Структура проекта

| Файл / каталог | Назначение |
|----------------|------------|
| `.env` | Параметры БД: `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`. Не публиковать реальные секреты. |
| `postgres_driver.py` | Класс `PostgresDriver`: загрузка `.env`, подключение, универсальные **`create` / `read` / `update` / `delete`** для любых таблиц. |
| `Models/user.py` | Таблица `users`, dataclass `User`, CRUD. |
| `Models/tables.py` | Таблица `dining_tables`, `DiningTable`, CRUD. |
| `Models/booking.py` | Таблица `bookings`, `Booking`, CRUD, **`check_table_availability`**, миграция FK и **`ON DELETE CASCADE`** для броней при удалении гостя или стола. |
| `seed_booking_data.py` | DDL из моделей, индексы, приведение FK, `TRUNCATE`, демо-данные: **5** пользователей, **7** столов, **10** броней. |
| `frontend.py` | Окно tkinter: вкладки пользователей, столов, броней; кнопка **«Проверить доступность»**. |
| `main.py` | Запуск приложения: `python main.py` → открывается GUI (`frontend.main`). |
| `test_postgres_connection.py` | Проверка соединения с PostgreSQL. |

Схема таблиц для бронирования создаётся скриптом **`seed_booking_data.py`**, а не драйвером: драйвер остаётся только транспортным слоем CRUD.

## Модель данных

- **`users`** — ФИО, телефон (опционально), `created_at`.
- **`dining_tables`** — метка стола (`label`, уникальная), вместимость, зона.
- **`bookings`** — `user_id`, `dining_table_id`, `starts_at`, `ends_at`, `party_size`.

Связи: у пользователя и у стола много броней. Удаление родителя каскадирует в `bookings`. Пересечение интервалов на одном столу блокируется логикой в `check_table_availability` и при создании/обновлении брони.

## Возможности

- **Данные:** универсальный доступ через `PostgresDriver`; для сущностей — функции CRUD в `Models/*.py`.
- **GUI:** просмотр и редактирование пользователей, столов и броней; формат времени `ГГГГ-ММ-ДД ЧЧ:ММ`; отдельная проверка доступности стола без создания записи.
- **Сидирование:** воспроизводимое наполнение БД для отладки и демонстрации.

## Запуск

1. PostgreSQL, созданная база (имя как в `.env`).
2. Настроить `.env`.
3. `pip install -r requirements.txt`
4. По желанию: `python test_postgres_connection.py`
5. Создать таблицы и данные: `python seed_booking_data.py`
6. Интерфейс: **`python frontend.py`** или **`python main.py`**

Команды выполнять из **корня проекта**.

## Итог

Получены: целостная схема БД с внешними ключами и каскадами, слой доступа без привязки к учебным таблицам «заказов», три доменные модели с CRUD, контроль пересечений броней по столу, демо-данные и GUI с обязательной проверкой доступности стола.
